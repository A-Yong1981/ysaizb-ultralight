# Ultralight-Digital-Human 智能参数配置与显存安全知识库

> 本知识库用于指导大模型与本地规则引擎，根据**用户提供的参考视频属性**与**用户自然语言需求**，自动生成安全、准确、开箱即用的 Ultralight 数字人构建配置。

## 1. 硬件红线与运行约束（当前主机）
- 显卡型号：NVIDIA GeForce RTX 2080 8GB（Turing 架构 `sm_75`，仅支持 FP16 与 FP32，不支持 BF16）。
- 显存红线：整机稳定显存占用建议控制在 **4.5GB 以内**，绝不允许 OOM。
- 因此训练参数 `batch_size` **严格上限为 16**（短片或显存紧张时用 `4` 或 `8`）；严禁建议超过 `16` 的 `batch_size`。

## 2. 三种构建模式（`mode`）选择规则
1. `"从头本地训练 + 导出ONNX"`（最常用）：
   - 适用条件：用户只提供了参考视频，没有现成 `.pth` / `.onnx` 权重文件。
   - 强制前提：**参考视频必须包含清晰真人说话音轨 (`has_audio=True`)**。
   - 禁止情况：若参考视频无音轨 (`has_audio=False`，例如闭嘴静音呼吸视频)，绝对不能推荐此模式去硬训，必须在 `warnings` 中明确提示用户“换一段带正常说话声音的正面视频”，或改用外部权重封装模式。
2. `"封装外部权重 (.pth/.onnx)"`：
   - 适用条件：用户已选择外部权重文件 (`has_ckpt=True` 且需求提到封装/已有模型/导入权重/不重新训练)，直接跳过训练，抽取视频帧与关键点并完成 `unet.onnx` 打包。
   - 此时视频允许没有音轨 (`has_audio=False`)。
3. `"断点续训 (.pth)"`：
   - 适用条件：用户选择了此前训练到一半的 `.pth` 权重并要求“继续训练/追加轮数/微调优化”。
4. **同主播换新衣服 / 复用已训形象（`--base_avatar`）**：
   - Ultralight UNet 仅驱动嘴部 `160x160` 区域，因此**同一位主播换穿不同服饰拍的新视频，可直接零训练（`epochs=0`）复用该主播已训练好的 `unet.onnx` 模型，十几秒即生成新服饰造型**（支持换穿西装、古风、休闲装做不同专场），新服饰视频甚至无需带音轨；只有当新服饰场景光照肤色差异很大时，才需要用 `epochs=10~20` 微调适配。

## 3. 音频特征路线（`asr`）选择规则
- `"hubert"`（25fps，CUDA FP16，约 ~1.3GB 显存）：
  - **默认最推荐路线**。嘴型同步精度最高、开合最自然、适应语速变化和普通话/外语。
  - 适用：正式直播、追求嘴型自然清晰、视频帧率为 25fps 或常规口播视频。
- `"wenet"`（20fps，纯 ONNX Runtime，显存 < 1GB）：
  - **轻量省显存路线**。
  - 适用：用户明确强调“省显存”“电脑性能吃紧”“同时开大型游戏/多开软件”“追求更快导出/极轻推理”。

## 4. 训练超参数推荐经验（`epochs`, `batch_size`, `lr`）
- **极速测试 / 先看看效果**（用户说“测试一下”“快速出个demo”“先看看能不能跑通”）：
  - `epochs`: `10 ~ 20`（通常建议 `15`；若用户只要几秒钟跑通验证可用 `5~10`）；
  - `batch_size`: 若视频较短（< 300 帧）用 `4` 或 `8`，较长用 `8` 或 `12`；
  - `lr`: `0.001`。
- **标准正式开播**（默认值，用户未提特殊限制或要求“正式开播”“清晰自然”“效果稳”）：
  - 若视频 `>= 90 秒`（约 >= 2000 帧）：`epochs = 100`，`batch_size = 16`（若总帧数 < 400 则取 `min(16, max(2, frames // 12))`），`lr = 0.001`，`asr = "hubert"`。
  - 若视频 `20 秒 ~ 90 秒`：`epochs = 120 ~ 150`（短素材适当多训几轮让口腔纹理收敛），`batch_size = 8 ~ 16`，`lr = 0.001`。
  - 若视频 `< 20 秒`：若用户非“测试”而是要求正式开播，应推荐 `epochs = 150`, `batch_size = 4 ~ 8`，同时在 `warnings` 温和提醒“当前参考视频仅 X 秒，正式长期开播建议后续换用 1~5 分钟不同口型说话视频以获更佳嘴型泛化效果”。
- **高精度极致嘴型**（用户说“不赶时间”“嘴型一定要极准”“高精微调”）：
  - `asr = "hubert"`，`epochs = 150 ~ 200`，`batch_size = 12` 或 `16`，`lr = 0.001`（断点续训微调可用 `0.0005`）。
- **省显存轻量长跑**（用户说“省显存”“边玩游戏边播”“低负载”）：
  - `asr = "wenet"`，`epochs = 100`，`batch_size = 8`，`lr = 0.001`。
- **外部权重封装**（`mode == "封装外部权重 (.pth/.onnx)"`）：
  - `epochs = 0`（跳过训练），`batch_size = 16`，`lr = 0.001`。

## 5. 输出 JSON 格式规范
必须输出单个合法 JSON 对象（不要加额外文字），字段如下：
```json
{
  "mode": "从头本地训练 + 导出ONNX | 断点续训 (.pth) | 封装外部权重 (.pth/.onnx)",
  "asr": "hubert | wenet",
  "epochs": 100,
  "batch_size": 16,
  "lr": "0.001",
  "set_default": true,
  "summary_title": "标准高画质开播方案",
  "reason": "用一句通俗中文向非技术用户解释为什么这样配（不堆砌晦涩术语，说明预计速度与效果）。",
  "warnings": "如视频无音轨或过短需提醒的注意事项；无则为空字符串"
}
```
